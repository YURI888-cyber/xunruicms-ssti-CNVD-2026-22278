# **XunRuiCMS SSTI 远程代码执行漏洞 PoC**
> CNVD‑2026‑22278 | 迅睿CMS（XunRuiCMS）服务端模板注入 / PHP代码执行漏洞

## 一、项目说明
本项目为 **CNVD‑2026‑22278** 的漏洞验证（PoC）代码与分析报告，仅用于安全研究与漏洞复现学习，禁止用于未授权生产环境攻击。

- **漏洞产品**：迅睿 CMS（XunRuiCMS）
- **漏洞类型**：服务端模板注入(SSTI)，最终造成任意PHP代码执行（CWE‑94）
- **漏洞等级**：高危
- **收录编号**：CNVD‑2026‑22278

## 二、漏洞原理
迅睿CMS模板引擎处理自定义`{code}`模板标签时，标签内的内容不会经过任何安全过滤、转义与沙箱校验。
模板编译流程：提取`{code}`标签内容 → 占位替换 → 模板编译 → 还原标签原始内容 → 通过`require`直接执行原始PHP代码，实现对模板编译器的完全绕过。

漏洞核心逻辑位于 `dayrui/Fcms/View.php` 文件，`{code}`标签的处理逻辑直接将用户可控内容交给require执行，没有做危险代码拦截。
攻击者**拥有后台管理员权限**时，可以在后台编辑模板，插入恶意`{code}`标签，写入PHP恶意代码，访问渲染后的模板页面即可触发代码执行。

> 注意：该漏洞**需要管理员后台权限**，不存在未授权利用场景。

## 六、修复建议

### **临时缓解**
1. 关闭后台在线模板编辑功能，限制管理员模板操作权限；
2. 模板目录设置为服务器不可写权限；
3. WAF 策略拦截模板请求中`{code}`标签相关载荷。

### **根本修复**
1. 方案一：直接移除危险的`{code}`模板标签功能；
2. 方案二：保留标签则增加严格内容过滤，禁止传入原始 PHP 执行代码；
3. 加固模板引擎编译逻辑，禁止未经过滤的原始代码直接 `require` 执行。

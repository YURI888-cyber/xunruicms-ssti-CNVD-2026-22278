# XunRuiCMS SSTI 远程代码执行漏洞 PoC

> CNVD-2026-22278 | 迅睿CMS（XunRuiCMS）服务端模板注入 / 代码执行漏洞

## 一、项目说明

本项目为 **CNVD-2026-22278** 的漏洞验证（PoC）代码与分析报告，用于安全研究与漏洞复现学习，不涉及生产环境攻击。

- **漏洞产品**：迅睿 CMS（XunRuiCMS）
- **漏洞类型**：服务端模板注入（SSTI）导致任意代码执行（CWE-94）
- **漏洞等级**：高危（可远程未授权/低权限执行系统命令）
- **收录编号**：CNVD-2026-22278

## 二、漏洞原理

迅睿 CMS 模板引擎在解析模板文件时，对 `{php}`、`{func()}` 等标签及模板内嵌表达式缺乏有效沙箱隔离。攻击者控制的可解析模板内容会被拼接后交由 `eval()` 执行，从而造成任意 PHP 代码执行。

问题核心位于 `dayrui/Fcms/Core/View.php` 中的 `_code()` 方法（约第 724–744 行）：该方法负责将模板标签转译为 PHP 代码并执行，但未对标签内的变量与函数调用做白名单校验与危险函数过滤。

结合迅睿 CMS 允许上传 `.html` 模板文件的业务逻辑，攻击者可将恶意 Payload 写入 `.html` 文件并触发解析，最终实现远程命令执行（如 `whoami`、`id` 等）。

六、修复建议
临时缓解
限制后台上传文件类型，禁止 .html / .php 等可解析后缀上传；
对模板目录设置不可写/不可执行权限，关闭模板在线编辑入口；
在 WAF 层拦截含 {php}、{func}、eval、system 等关键字的请求体。
根本修复
移除模板引擎中的 eval() 执行路径，改用白名单式标签解析器；
对所有模板变量执行严格的输出编码与上下文隔离；
引入沙箱机制，禁用 system、exec、passthru、shell_exec 等危险函数。
